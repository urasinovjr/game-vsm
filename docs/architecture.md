# Архитектура

Android APK объединяет вертикальную Flutter-оболочку, горизонтальную Unity-сцену и локальный движок сценария на Kotlin. Flutter создаёт учебный профиль и показывает результаты через Android MethodChannel. Unity вызывает тот же движок из отдельной Activity. Профили, попытки, события и очередь будущей синхронизации хранятся в SQLite внутри приложения.

Сценарий создаётся в `server/scenario.py` и экспортируется в `app/android/app/src/main/assets/scenario.json`. Локальный движок повторяет переходы, таймеры и начисление очков из `server/engine.py`. Граф сценария сохраняется вместе с попыткой, чтобы обновление приложения не меняло незавершённую смену. Учебные таймеры считают только время активной игры и останавливаются при сворачивании.

FastAPI остаётся отдельным сервером для будущей синхронизации, аналитики и общего рейтинга. Пока публичный сервер не настроен, APK полностью работает локально, а общий рейтинг честно обозначен как недоступный. Перед включением синхронизации сервер должен повторно рассчитывать результат по истории действий и принимать повторную отправку без двойного начисления.

Для выпуска Unity экспортирует `unityLibrary-release.aar`, затем Flutter собирает один arm64 APK. Unity-библиотека и модель поезда хранятся в Git LFS; ключ подписи и артефакт выпуска остаются вне Git. Материалы организатора в `docs/sources/` служат предметной основой, а баллы и лимиты времени остаются учебными параметрами демо.
