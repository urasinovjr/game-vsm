# Требования к приложению

Основание — [ТЗ организатора](sources/2026-09-25/organizer-requirements.pdf) и [материалы по поезду и рабочим ситуациям](sources/2026-09-25/organizer-dataset/README.md). Приложение предназначено для обучения проводников ВСМ на вымышленных данных.

Полное решение должно содержать профиль с прогрессом, уровнями и очками компетенций; нелинейные сценарии с условиями, таймерами и последствиями; шкалы лояльности пассажира и безопасности; достижения; рейтинг внутри бригады, депо и компании; подробный разбор решений; уведомления; аналитику пробелов в навыках; документированный API для HR/LMS. Клиент и сервер разделены, результаты и данные попыток хранятся на сервере.

Текущее ядро реализует одну смену с ветвлениями, таймерами, двумя шкалами, сохранением попытки, базовыми достижениями, общим рейтингом и личной аналитикой. Программа на пять дней в [макете](https://www.figma.com/design/OCKHKOEylCubp3ekk8ZNeS/%D0%92%D0%A1%D0%9C?node-id=0-1) — цель интерфейса; остальные четыре дня нельзя показывать как доступные сценарии, пока они не созданы. Не завершены уровни, группы рейтинга, механизм новых уведомлений, каталог сценариев и контракт HR/LMS.

Регламенты и изображения организатора используются как предметный источник. Там, где материал не даёт размера или однозначной процедуры, игровая реконструкция остаётся условной. Баллы и временные лимиты демо не обозначают профессиональный допуск.
